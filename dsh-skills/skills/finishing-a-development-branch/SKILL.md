# Finishing a Development Branch

## 何时使用

实现已完成、测试通过，需要决定如何整合工作。

## 核心原则

验证测试 → 检测环境 → 呈现选项 → 执行所选 → 清理。

## 流程

### 1. 验证测试
合并选项前提是测试必须通过。先运行测试，失败则中止并报告。

### 2. 检测环境
判断当前 HEAD 是否为 detached、是否存在工作区/分支布局。

### 3. 呈现选项
用结构化提问工具呈现选项，不要以纯文本罗列。被跳过/驳回/自动解析的答案不算同意——停下来用文本再问。

- **正常分支/命名分支工作区**：呈现 4 个选项：
  1. 本地合并（合并回 base 分支，对结果运行测试，删除功能分支）
  2. 创建 Pull Request（推送 origin 并通过 gh cli 打开 PR）
  3. 保持现状（分支与工作区原样保留，稍后处理）
  4. 丢弃工作（永久删除该分支及其所有提交，需确认）
- **detached HEAD**：呈现 3 个选项（省略"本地合并"），并说明 HEAD 分离故无法合并。

### 4. 执行所选
- 本地合并：切到 base 分支 → 合并 → 测试 → 删除功能分支
- 创建 PR：推送分支 → `gh pr create` → 报告 PR 链接
- 保持现状：什么都不动
- 丢弃：先确认，再删除分支

### 5. 清理工作区
合并/PR/丢弃后清理工作区；"保持现状"不清除。

## 红旗

- 测试未通过就呈现选项
- 呈现选项前未检测环境
- 丢弃选项未获得明确输入确认
- 合并/PR/丢弃选项未执行工作区清理
