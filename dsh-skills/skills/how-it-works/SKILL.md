# How It Works

## 何时使用

用户询问"如何工作 / 这是做什么的 / 机制是什么 / 数据存在哪里"类问题：
- 某工具或组件如何捕获/记录信息
- 记忆或状态注入何时触发、以什么形式生效
- 数据存储位置与生命周期
- 组件之间的调用与数据流

## 核心原则

- **解释机制而非罗列功能**：说清数据从哪来、经过什么处理、落到哪里、何时被读取
- 以事实为准：优先依据源码、文档或实测，不臆测
- 结构清晰：输入 → 处理 → 存储 → 触发 → 输出

## 流程

1. 明确用户想问的对象与层面（触发时机 / 存储位置 / 注入形式 / 调用链）
2. 查阅源码或文档确认真实行为
3. 用分层或分阶段的方式解释机制
4. 涉及数据时明确：捕获点、处理、落盘位置、读取/注入时机
5. 给出验证方法（如查看日志、数据目录、调试命令）

## 回答结构建议

- 一句话结论
- 机制分步说明（含触发条件）
- 数据位置（文件/存储路径、格式）
- 边界与注意点（如权限、生命周期、清理）

## 注意

- 区分"设计意图"与"实际行为"，二者不一致时如实说明
- 提供可自行验证的路径（命令、目录、日志）
