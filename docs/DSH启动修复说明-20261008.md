# DSH Manager 启动修复说明（computer-use bundles 残留导致 dsh 无法启动）

## 一、问题根因

DSH 启动崩溃的报错（来自 dsh-app-boot）：

    Error: dsh: profile bundle "@deepseek-ai/dsh-computer-use" declares no dsh.bundle in its package.json

- **profile 清单** `~/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles` 中
  残留了两个旧版错误登记的包：
  - `@deepseek-ai/dsh-computer-use`
  - `@deepseek-ai/dsh-experimental-computer-use-cua-driver-native`
- 这两个官方 computer-use 包是**普通库**，package.json 里没有 `dsh.bundle` 字段；
  新版 dsh CLI（0.1.6-alpha.1）内嵌的 `dsh-app-boot/loadProfileDirectory` 对 bundles
  做**硬校验**：每个 bundle 必须声明 `dsh.bundle.patch`，否则直接 throw → DSH 启动即退出。
- 早期 DSH Manager 版本是把 computer-use 登记进 bundles 的错误做法（正确做法见下）。
  `packages/core/src/computer-use.js` 已内置 `cleanLegacyBundles()` 清理函数，但
  只在该模块被调用（安装/开关/卸载/查询状态）时触发，**DSH 启动路径没有调用**。

## 二、现场修复（已执行，已验证）

- 备份：`~/.dsh/profiles/web/package.json.bak-<时间戳>-computeruse-cleanup`
- 从 `dsh.profile.bundles` 移除上述两个包，其余 bundle 保留。
- 验证：以 dsh CLI 直接启动 web（port 3999），HTTP 401 表示 DSH 服务已就绪
  （0.1.2+ 无 token 访问根路径返回 401 即服务正常）。
- **用户操作**：重新打开 DSH Manager → 点击「启动 DSH」即可。

## 三、代码修复（本补丁，防复发）

1. `packages/core/src/computer-use.js`：`cleanLegacyBundles` 改为导出（`export function`）。
2. `packages/core/src/index.js`：导出 `cleanLegacyBundles`。
3. `electron/ipc-handlers.js`：`spawnDSHWeb` 启动 DSH 前幂等调用
   `cleanLegacyBundles('web')` —— 与既有「凭据文件迁移 / LLM 配置清洗 / 能力路由
   插件安装」同为启动自愈链路。
4. `src/assets/css/style.css`：调试日志面板（#debugLogContent 等）开放鼠标选择复制
   （`body { user-select:none }` 全局禁选导致日志无法用鼠标选中）。

### 应用方式（三选一）

**方式 A：git apply（推荐）**
    cd Y:////AI-DATA////dsh-manager
    git apply "C:////Users////Administrator////AppData////Local////Temp////dshfix////dsh-manager-fix-XXXX.patch"

**方式 B：使用仓库内 .new 交付文件覆盖**
    copy /Y packages\core\src\computer-use.js.new packages\core\src\computer-use.js
    copy /Y packages\core\src\index.js.new         packages\core\src\index.js
    copy /Y electron\ipc-handlers.js.new             electron\ipc-handlers.js
    copy /Y src\assets\css\style.css.new            src\assets\css\style.css

**方式 C：桌面端手工合并**（推荐给不熟悉命令行的场景）
    用 DSH Manager 桌面端 / 任意编辑器打开四个文件的 .new 版本，参照上面说明手工合并。

## 四、原理解析：computer-use 正确挂载方式

- 这两个包**不能**进 `dsh.profile.bundles`（无 dsh.bundle）。
- 正确方式：`cordis.patch.yml` 的 insert 块（见 computer-use.js 的 CU_PATCH_BLOCK）：
  - `- insert: - id: dsh-manager-computer-use-service, name: '@deepseek-ai/dsh-computer-use'`
  - `- insert: - id: dsh-manager-computer-use-provider, name: '@deepseek-ai/dsh-experimental-computer-use-cua-driver-native'`
- DSH Manager「电脑控制」页的「一键安装」即按此方式挂载，并幂等清理旧 bundles 残留。

## 五、日志「鼠标选择复制」说明

- 现象：调试日志面板只能靠「📋 复制（全部）」按钮复制，无法鼠标选中部分内容。
- 原因：`src/assets/css/style.css` 的 `body { user-select:none }` 全局禁选文本。
- 修复：对日志面板/代码块/输入框区域恢复 `user-select:text`（本补丁第 4 项），
  鼠标拖动选中 + Ctrl+C 即可复制选中片段。
