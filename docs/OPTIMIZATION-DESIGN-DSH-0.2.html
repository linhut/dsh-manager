一、规范适用性判定

DSH Manager 不是 DSH 插件包：不上架 dsh plugin add，不声明 dsh.bundle，也不进 profile。它是 DSH 的桌面宿主。因此官方规范需分三类处理，不能整篇照搬。

官方条款原文要求本项目映射适用性
显式依赖 inject服务名与消费名完全匹配，缺失依赖不上线IPC 通道即服务契约：名字、入参、返回必须单一来源直接适用
生命周期可逆副作用登记 disposer，卸载后行为完全还原handler 模块、页面、webview 均需可完整卸载直接适用
跨端物理隔离Browser 端不调 Node 原语，Host Context 不外泄主进程 / preload / 渲染进程 / webview 四层边界直接适用
配置 schema 校验非法输入明确报错，不静默兜底IPC 入参校验 + settings.yaml 结构校验直接适用
一切皆插件能力解耦，独立装卸147 个通道按域拆分，注册即副作用转译适用
Bundle / Profile 层序patch 层按序组合，后层胜出本项目是这些对象的操作方，需正确呈现层序转译适用
defineTool / UI 卡片工具契约、卡片纯函数不注册模型工具，不涉及不适用

四、六项专项设计

1. 契约单一来源

electron/contract/channels.js 作为唯一清单，每条声明 domain / args / result / mutating / longRunning；preload 方法启动时生成，不再手写。新增通道必须同时改清单、实现、契约测试三处，CI 双向校验数量与名称一致。

消除的重复

  • preload.cjs 约 230 行平铺方法
  • 通道改名需全局搜索的隐患
  • 渲染端字符串直调 invoke

新增的约束

  • 入参越界在 Transport 层即被拒
  • 事件通道同样入清单，返回取消订阅函数
  • 清单 ↔ 注册 ↔ 方法三方一致脚本

2. 统一响应信封与错误码

主进程统一包装：成功 { ok:true, data }，失败 { ok:false, code, message, detail }。错误码固定 10 类（INVALID_ARGS / NOT_INSTALLED / PORT_IN_USE / PERMISSION_DENIED / TIMEOUT / CANCELLED / DEPENDENCY_MISSING / UPSTREAM_ERROR / INTERNAL / OK），UI 文案在渲染端一处映射，不再解析 Electron 的报错字符串。

这是破坏性变更：先用 legacy:true 兼容层保持原样返回，按域逐个切换，全部切换后删除兼容层。

3. 安全边界（P0）

措施要点
webview 独立会话<webview partition="persist:dsh-web">，与主窗隔离；代价是用户需重新登录 DSH，更新说明明示
挂载前强校验will-attach-webview 中剥离 prefs.preload、强制 nodeIntegration=false、src 必须命中本地白名单
权限默认拒绝setPermissionRequestHandler 对摄像头/麦克风/定位/通知一律 false，按 origin 白名单将来放行
路径沙箱所有接受路径的通道 realpath 后校验允许根，拒绝 .. 与符号链接逃逸
命令执行禁止字符串拼接，统一 execa(file, args[])；版本号、registry 走白名单/正则
CSPmeta + onHeadersReceived 双保险；内联样式需评估后再收紧 style-src

4. 生命周期与资源所有权

引入 HostScope：effect(fn) 收集 disposer，dispose() 逆序逐个 await、重复调用幂等、子作用域递归释放。所有资源登记在案——ipcMain.handle、webContents 事件、webview 实例、定时器、子进程、fs.watch、autoUpdater。

验收方式：启动应用 → 逐页打开再关闭 → 释放全部 scope → 断言通道 0、活跃定时器 0、子进程 0、全局监听器不增长。这条断言就是规范里"提前卸载后确认资源没有留下"的等价物。

5. DSH 运行时状态机

状态转换

  • IDLE → CHECKING → STARTING → READY
  • READY → STOPPING → IDLE
  • 任一环节失败 → FAILED（可重试，不无限重试）

硬规则

  • start 在 STARTING/READY 时幂等返回
  • 重启必须等 stop 完成且健康检查通过才算 READY
  • 崩溃最多自动重启一次，第二次只提示

同时把 DSH 的错误分类（CONTENT_REFUSED / AUTH / QUOTA / RATE_LIMIT / TRANSPORT / TIMEOUT）映射为界面处置建议，而不是统一显示"启动失败"。

6. 前端可维护性与工程门禁

三步走，不做大爆炸重写：① 模块改 ESM，全局类挂 window 过渡；② 页面统一 { mount, unmount } 契约，切页即资源回收；③ 去 innerHTML 分三批——先做拼接了外部数据的 XSS 面，再静态模板，最后复杂列表。

门禁工具门槛
格式Prettier全仓一次性格式化，此后 --check
静态检查ESLint flat config禁 innerHTML、禁字符串 execa、no-floating-promises
类型jsconfig + checkJs先覆盖 contract 与 core，再逐步扩大；不全面重写 TS
契约一致性自研脚本清单 ↔ 注册 ↔ 方法三方一致，缺一即失败
测试node --test保留现有 25 个，新增契约/校验/隔离/生命周期四类
发布CI 权限分离contents:write 只给发布 job，构建 job 只读

测试纪律对齐规范禁止项：不 mock 被测模块内部函数，不写"源码里必须出现某符号"的正则守卫，不测私有字段与调用次数。

六、取舍与风险

决策代价缓解
不全面重写 TypeScript类型收益延后jsconfig + JSDoc 先在契约层拿到保护，成本最低、收益最高
不引入前端框架复杂列表仍手写渲染h() + DocumentFragment 足够；页面稳定在 10 个，无框架刚需
信封改造属破坏性变更147 个通道返回形状变化legacy 兼容层 + 按域切换，每域切换后跑该域测试
webview 改独立 partition用户需重新登录 DSH更新说明明示；提供"沿用旧会话"过渡设置
开启 sandbox需实测 preload 依赖单独分支验证，失败则保持 false 但补齐其余隔离

七、验收清单

契约与隔离

  • 清单条目数 = 注册数 = preload 方法数
  • 非法入参不进入业务实现
  • 渲染端无字符串直调 invoke
  • webview 独立 partition 且 preload 被剥离
  • 越界路径（含符号链接）被拒

可逆与运行时

  • 释放 scope 后无残留通道/定时器/进程
  • 反复 dispose 幂等
  • 切页 10 次内存无单调增长
  • 连点启动只产生 1 个进程
  • 重启后健康检查通过才 READY
