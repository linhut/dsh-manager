# DSH Manager v1.3.14-test.13 验收测试清单

> 本清单验证三个核心问题修复（①能力路由 ②图片上传/识别 ③AI 生图）
> **以及用户最新反馈的问题**：
> - **A. 配置/默认模型未应用到对话、路由是否生效不清楚**（「📡 路由日志」面板可看真实切换记录）
> - **B. DSH 已在运行时 Manager 打开后无法显示运行页面**（token URL 持久化 + 端口复用）
> - **C. DSH 由外部启动（非管理器托管）时，Manager 也能识别"运行中"并引导重启接管**（运行时探测兜底）
> - **D. 版本更新提示点击跳转到版本管理模块**（统一入口，避免多头处理）
> 全部通过后即正式发布 v1.3.14。

## 一、安装与准备

1. 安装 `dist/DSH-Manager-1.3.14-test.13.exe`（覆盖旧版本）
2. 启动 Manager，打开「调试日志」面板确认日志出现：
   - `能力路由插件就绪（copied 或 already-exists）`
   - `LLM 提供商配置已自动迁移/清洗`（启动时自动给视觉模型补 input 声明）
3. 启动 DSH

## 二、新问题验证（重点）

### A. 配置/默认模型应用到对话 + 路由日志可见
> DS H 的「默认模型」只对**新建会话**生效；能力路由（发代码→代码模型、发图片→识图模型）在每次请求时自动切换，
> 用「📡 路由日志」面板可看到真实切换记录。

| # | 操作 | 预期 |
|---|------|------|
| A.1 | Manager → LLM 能力路由页，配置 semantic/vision/code 三个能力并保存 | 保存成功提示 |
| A.2 | 点击「⭐ 设为默认」（语义） | 提示已应用为 DSH 默认模型（仅新建会话生效） |
| A.3 | 在 DSH **新建一个会话**（不是旧会话） | 会话默认模型应为你设的语义模型，无需手动选择 |
| A.4 | 在 DSH 发一条普通消息，然后在 Manager 能力路由页点「📡 路由日志」→「🔄 刷新日志」 | 面板出现 `[loaded]`（插件已加载）、`[attached]`（会话已挂载）、`[route]`（本次请求模型切换记录） |
| A.5 | 发一条含代码的消息，再刷新路由日志 | 出现新的 `[route]` 行：… ⇒ 代码模型（deepseek-v4-flash） |
| A.6 | （可选）发一张图片消息，刷新路由日志 | 出现 `[route]` 行：… ⇒ 识图模型（glm-5v-turbo） |

### B. DSH 运行中打开 Manager 能识别并显示
| # | 操作 | 预期 |
|---|------|------|
| B.1 | 启动 DSH 后，**完全退出 Manager**（确认 DSH 仍在运行：浏览器访问 127.0.0.1:3080 能看到 DSH） | DSH 继续运行 |
| B.2 | **重新打开 Manager** | 控制台应自动显示 DSH 页面（带鉴权，不再白屏） |
| B.3 | 若 B.2 显示"检测到 DSH 运行中但缺少鉴权令牌" | 点「🔄 重启 DSH」由 Manager 重新托管后应正常显示 |
| B.4 | 反复开关 Manager（DSH 保持运行） | 每次打开都能显示运行中的 DSH 页面，不会重复启动第二个 DSH |

### C. 外部启动的 DSH 也能被识别（本次新增）
> 场景：DSH 不是通过 Manager 启动的（命令行/网页/其他工具），Manager 打开后应识别"运行中"，
> 而不是显示"未安装"导致控制台空白、无法接管。

| # | 操作 | 预期 |
|---|------|------|
| C.1 | 用命令行/其他方式启动 DSH（或在 DSH 运行中重开 Manager 且非 Manager 托管） | 侧边栏显示「DSH 运行中（安装路径未识别）」，而不是"未安装" |
| C.2 | 控制台区域 | 显示"检测到 DSH 服务已运行，但它不是由管理器启动的"占位 + 「🔄 重启 DSH」按钮（不再空白） |
| C.3 | 点击「🔄 重启 DSH」 | Manager 接管：停止旧实例重新托管启动 → 控制台正常显示页面 |
| C.4 | 重启后发一条代码消息，看路由日志 | 有 `[route]` 记录（能力路由在接管后生效） |

### D. 版本更新提示跳转版本管理（本次新增）
| # | 操作 | 预期 |
|---|------|------|
| D.1 | 启动 Manager 15 秒后若检测到 DSH 新版本 | 出现顶部 banner 与 toast 提示 |
| D.2 | 点击 toast 的「前往版本管理」或 banner 的「前往版本管理」 | 跳转到「📦 版本管理」页（统一处理升级），不再在提示里直接升级 |
| D.3 | 若无新版本 | 无提示（此项可跳过，属正常） |

## 三、原三问题回归

### ① 能力路由是否生效
| # | 操作 | 预期 |
|---|------|------|
| 1.1 | 打开 DSH **设置 → 插件**，确认存在 `@dsh-manager/dsh-capability-router` 且已启用 | 插件列表可见 |
| 1.2 | 打开一个**旧会话**，发送"写一个冒泡排序" | 应切换到代码模型（deepseek-v4-flash），路由日志可见 [route] |
| 1.3 | 发送普通问题"你好" | 应使用语义模型 |
| 1.4 | Manager 路由日志搜 `[capability-router]` | 有路由切换记录 |

### ② 图片上传/识别
> ⚠️ **关键**：DSH 的图片准入检查使用「当前会话模型」，必须先在 DSH 会话把模型选为 `glm-5v-turbo`。

| # | 操作 | 预期 |
|---|------|------|
| 2.1 | DSH 会话右上角选择模型为 `glm-5v-turbo` | 模型切换成功 |
| 2.2 | 上传一张图片并发送"这张图里有什么？" | 不再提示"当前模型不支持图片"，能正常识别 |
| 2.3 | 若仍失败，检查设置 → LLM 提供商 → yang-newapi → 确认 `glm-5v-turbo` 的「🖼️识图」已勾选，保存后重启 DSH | 模型配置含 input:["text","image"] |

### ③ AI 生图
| # | 操作 | 预期 |
|---|------|------|
| 3.1 | 侧边栏点击「🎨 AI 生图」 | 页面打开，提供商/模型下拉有 yang-newapi 的模型 |
| 3.2 | 选择提供商、模型，输入提示词，点「生成」 | 图片生成成功并显示预览 |
| 3.3 | 点「打开图片文件夹」 | 打开 `用户目录/dsh-manager/images/`，图片已保存为文件 |
| 3.4 | 若生成失败 | 记录错误提示（如模型不支持 /images/generations）反馈给我 |

### ④ 回归（确保没破坏旧功能）
| # | 操作 | 预期 |
|---|------|------|
| 4.1 | 正常对话 | 语义模型正常回复 |
| 4.2 | LLM 提供商增删改查 | 正常 |
| 4.3 | 市场/技能/插件页 | 正常展示 |
